# KEDDEH SYSTEMS ESTATE DEPENDENCY FEDERATION R32

Authority: overlay on Unification Control Standard R1. R1 history remains immutable.

## Purpose

R32 binds current proven BRAINK resident-root, carrier-last and fail-closed host-trust processes into the supporting repository estate without collapsing sector ownership.

## Mandatory invariants

1. Carrier is projection, never identity.
2. Resident root identity and source digests are resolved before trusting network endpoint, host, DNS, cloud or server carrier.
3. Structural qualification is not physical-host verification.
4. TRUST_BOUND is not VERIFIED physical execution.
5. VFS is resolver/namespace only. It is not storage medium or capacity authority.
6. Storage primitive is encoded medium → zero-less geometry → KEX storage controller → logical objects → VFS resolver.
7. Source line, sheet row, registry row and manifest label are provenance/projection, not storage allocation.
8. Public/external claims require owning actuator mutation plus independent external readback.
9. Repo names do not establish authority. Authority follows executed mechanics and the estate promotion gates.
10. R31 is a required durable-transition interface in this overlay, not silently declared executable until its concrete implementation and receipts are located and read back.

## Repository federation

- BRAINK: orchestration, resident root graph, carrier-last remote join, host evidence/trust boundaries.
- GENERAL-GOVERNANCE-: definitions, promotion/evidence gates, estate dependency control.
- SERVERS-KEDDEHSYSTEMS: generic server listeners, host binding, DNS execution mechanics; consumes resident root + trust state before server promotion.
- kcloud-substrate: cloud allocation/substrate candidate; consumes server, storage, host-trust and external-readback gates.
- virtualized-storage: K-DRIVE/storage canonical candidate; owns encoded-medium/controller/persistence candidates, not VFS-as-medium.
- VIRTUALISED_MEMORY: supporting storage/memory evidence; feeds comparison and migration proof into storage authority.
- KEDDEH_SOFTWARE_NODES: software-node/network-fabric candidate; carrier identity is subordinate to resident root identity and host trust.
- KEDDEH-CLOUD-SERVERS-ID-1: mixed supporting carrier; functions must route to cloud, server or storage authority rather than retain duplicate ownership.
- kex-braink-substrate: KEX/BRAINK shared candidate; KEX identity/address/execution semantics separate from BRAINK orchestration/observer state.
